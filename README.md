# 反诈先锋 - 防骗情景模拟

一款纯前端的网页文字反诈游戏。抽一张身份牌，回到被骗之前，在 6 个真实诈骗场景里做选择——每选错一次，信息就往黑产手里多流一层。

**打开即玩，无需安装。** 游戏本体是单个 `index.html`，不依赖任何第三方库；手机端体验最佳。

在线试玩：https://xiguahahaha.github.io/FZXF/

> ⚠️ 本游戏为**情景模拟**，「写点知识」出品，**非官方产品**。文中金额与情节均为虚构设定，请勿当作真实案例。

## 玩法

1. **抽一张身份牌** —— 中年人（守住养老钱）/ 青年人（帮父母挡坑）/ 老年人（守住棺材本）
2. **开局抽 6 关** —— 每局从对应身份线的关卡池里随机抽 6 关
3. **高仿微信聊天里做抉择** —— 每关三个选项，都像正常人真会做的选择
4. **结算** —— 防骗分（满分 100）、等级榜百分位、防骗笔记、防骗性格测试、留言墙

| 身份线 | 关卡池 | 典型骗局 |
|---|---|---|
| 中年 | 25 关 | 冒充客服、刷单、杀猪盘、冒充公检法、荐股、ETC 失效、征信「洗白」、代理退保、营业执照「年报」 |
| 青年 | 25 关 | 游戏账号担保、裸聊敲诈、注销校园贷、境外高薪、跑分洗钱、假房源、网课退费、求职内推费、数字藏品、代练盗号 |
| 老年 | 25 关 | 冒充孙子、养老金认证、民族资产解冻、收藏品鉴定费、上门安装、以房养老、社保「补缴」、养老院押金、算命消灾 |

中年局会掺入 1 关老年线的骗局（老年局反之），模拟「骗子不按年龄线出牌」的现实。

## 特色

- **三档判定**：不是简单的对错两分。选对了是**守住**；选错了但没全错、信息没外流是**中招**；全错的那种才叫**泄露**。三项互斥，相加恒为本局关数。
- **每关即时复盘**：每次选择后都会给一页复盘——先告诉你这一选实际发生了什么，**选错时直接摆出「✅ 正确做法」**（把正确选项的具体动作原文给你看），最后附一条能记住的防骗知识点。
- **防骗笔记（错题本）**：结算后生成独立一页，按「⚠️ 需要复习 / ✅ 已经守住」分区罗列本局 6 关，错过的关会显示「我当时选了…」，顶部给出「本局最该记住的一条」。整页也是一张**可直接保存的图片**（手机长按即可存相册）。
- **防骗性格测试（16 型）**：12 道情境题，从四个维度给出 16 型性格之一，附画像与针对性建议。**独立题库，不玩也能测**；同一套答案结果恒定。测过之后，防骗笔记里会多出一块性格区。结果是一张**可直接保存的图片**。
- **留言墙**：结算页底部的公开留言板，说说自己差点被骗的那一次。发言门槛是**必须先玩过一局**，且留言会自动带上本局成绩与身份线。
- **打击百分位**：结算页显示你打败了百分之多少的人（同分段的近似百分位，纯前端计算）。
- **全球人次**：首页显示累计完成人次，结算页显示你是第几位。

## 如何运行

**方式一：直接双击** `index.html`，浏览器打开即玩。

**方式二：本地预览服务器**（推荐，避免个别浏览器对 `file://` 的限制）
双击 `serve.bat`，会自动打开 `http://localhost:8080`。
> 没有 Python 时，改用 `npx serve` 或 VS Code 的 Live Server 插件。

## 如何修改内容

所有关卡、话术、选项、知识点都集中在 **`levels.js`**，按身份线分三个数组：`mid`（中年 25 关）、`youth`（青年 25 关）、`elder`（老年 25 关）。三条线共用同一套结构：

```js
{
  title:'关卡名',
  intro:['来源标签','一句话引子'],
  chat:[ {who:'scam',text:'骗子说…'}, {who:'me',text:'你回…'}, … ],  // 高仿聊天
  leakExtra:'（信息已泄露）后续精准话术补刀',                          // leakLevel>0 时显示
  options:[
    {tag:'best', label:'最优选择文案', verdict:'safe', vtext:'🛡️ 脱险',    desc:'复盘', leak:0},
    {tag:'ok',   label:'次优选择文案', verdict:'risk', vtext:'⚠️ 中招',    desc:'复盘', leak:0},
    {tag:'bad',  label:'最差选择文案', verdict:'hit',  vtext:'💥 信息泄露', desc:'复盘', leak:1},
  ],
  kp:'防骗知识点'
}
```

**三档判定口径**（三档互斥，相加恒为 5）：

| `tag` | 含义 | 计入统计 | 计分 |
|---|---|---|---|
| `best` | 选对了，成功守住 | 守住关数 | +20 |
| `ok` | **中招**：选错了，但没全错、信息没外流 | 中招关数 | −10 |
| `bad` | **泄露**：全错的那种，信息已外流 | 泄露次数 | −25 |

> 三档的措辞由 `VTEXT` / `VSUB` 两个映射统一管理，改文案不用动 150 条关卡数据。难度公式在 `index.html` 的 `endGame()` 里。

**加关**：往对应身份线的数组里照格式新增一个对象即可，游戏会自动纳入随机池。
**改话术**：直接改 `chat` / `options` 的文案。

### 新增关卡时的文案标准

选项的**迷惑性**是这个游戏的核心。三个选项都要是「正常人会做的选择」，靠细节差异区分，不靠情绪词：

1. **正确项给具体动作，不给态度表态** —— 写「打银行卡背面的官方客服电话报卡号查这笔消费」，不写「这是骗局，直接拉黑」
2. **错误项要听起来合理，只是省了关键一步** —— 写「问了对方工号和部门，觉得对得上就照做」，不写「怕连累家人所以转账」
3. **禁用情绪暗示词** —— 「怕」「心疼」「慌」「心动」「不舍得」这类词等于在提示「选这个就是被操控了」；三个选项的长度和语气要对齐

中间项（`ok`）的标准是「部分正确但不彻底」：守住了钱但泄露了信息，或加了微信但没给验证码。

> 改完刷新浏览器即可生效，无需构建。

## 技术说明

- **游戏本体零依赖**：结构、样式、逻辑都在单个 `index.html` 里，改完无需构建。
- **关卡数据可远程覆盖**：页面会尝试拉取线上关卡数据覆盖本地兜底，拉不到就静默退回本地，不影响游玩。所以加关改话术只需要更新数据文件，网页本体不用重新部署。
- **留言墙后端是 Supabase**：唯一需要外部服务的功能。用 Postgres 存留言，前端通过 REST 读写；发布走一个数据库函数（RPC），**限流逻辑放在数据库侧**——前端那个冷却只改 localStorage 就绕过了，只有服务端的计数才算数。
- **留言墙的安全模型**（三层）：
  1. 表开启 RLS；
  2. 匿名角色只被授予 `SELECT` / `INSERT`，**显式 revoke 掉 `UPDATE` / `DELETE`** —— 所以任何人按 F12 也删不掉、改不了别人的留言；
  3. 前端只查 `is_hidden = false` 的行，后台隐藏的留言对访客不可见。
  前端**不持有任何删除凭据**，删除只能从后台做（见下节）。
- **近似百分位**：静态站没有数据库，思路是借第三方免费计数服务当「分桶存储」——把分数划成 11 段，每段一个独立计数器，读回来在前端算百分位。属于近似值（分段粒度较粗，同段内不区分高低）。
- **人次统计**：同样走第三方免费计数服务（[Abacus](https://abacus.jasoncameron.dev)），到达结算页才算 1 人次。服务不可达时自动降级为本机计数，不报错。
- **站内返回**：接入了 History API，手机上的侧滑返回和浏览器后退是**在站内退上一层**，不会把整个页面退掉。
- **结果卡是画出来的**：16 型结果卡不是 DOM 排版，而是用 Canvas 绘制成图片后再以 `<img>` 显示——所以手机上长按就能存相册，且所见即所存。
- **移动端适配**：聊天气泡布局为窄屏优化，输入框字号设为 16px 以避免 iOS 聚焦时自动放大页面。

## 留言墙的部署与管理

留言墙是唯一需要后端的功能，其余部分不依赖它——**即使后端没配好，游戏也能正常玩**，只是留言区会提示「留言功能还在准备中」。

- **首次部署**：见 **`留言墙部署指引.md`**，或直接把 `建表SQL.txt` 粘贴进 Supabase 的 SQL Editor 执行（**可重复执行**，幂等）。
- **连不上时排查**：打开 `netcheck.html`，它会区分「网络问题」和「部署问题」。
- **日常管理**（隐藏/删除留言）：打开 `留言管理.html`，填入 Supabase 的 **Secret key**。
  推荐优先用「隐藏」而不是「彻底删除」——隐藏后前端立刻不显示，但数据保留，误删可恢复。
  > 也可以直接在 Supabase 控制台的 Table Editor 里操作，或对 `messages` 表执行：
  > `update public.messages set is_hidden = true where id = ?;`
- ⚠️ **Secret key 是全权限凭据**，能绕过所有安全规则。`留言管理.html` 只应在本机打开，用完后建议到 Supabase 撤销该 key。切勿把它写进 `index.html` 或任何会公开的文件里（`index.html` 里那个 `sb_publishable_…` 是**公开**级别的 key，设计上就是给浏览器用的，没有写/删权限）。
