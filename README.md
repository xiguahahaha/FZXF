# 反诈先锋 · 防骗情景模拟

一款纯前端的网页文字游戏。抽一张身份牌，回到被骗之前，在一局 6 个真实诈骗场景里做选择——
每选错一次，个人信息就往黑产手里多流一层。

**打开即玩，无需安装、无需注册。** 游戏本体是单个 `index.html`，零第三方依赖；手机端体验最佳。

**在线试玩**：https://xiguahahaha.github.io/FZXF/

> ⚠️ 本游戏为**情景模拟**，「写点知识」出品，**非官方产品**。
> 文中金额、人名、公司名均为虚构设定，请勿当作真实案例。

---

## 玩法

1. **抽一张身份牌**
   中年（守住养老钱）/ 青年（帮父母挡坑）/ 老年（守住养老钱）
2. **开局随机抽 6 关**
3. **在高仿聊天界面里做抉择** —— 每关三个选项，都像正常人真会做的选择
4. **结算** —— 防骗分（满分 100）、打败多少人、防骗笔记、防骗性格测试、留言墙

| 身份线 | 关卡池 | 典型骗局 |
|---|---|---|
| 中年 | 25 关 | 冒充客服、刷单返利、杀猪盘、冒充公检法、荐股、ETC 失效、征信「洗白」、代理退保 |
| 青年 | 25 关 | 游戏账号担保、裸聊敲诈、注销校园贷、境外高薪、跑分洗钱、假房源、网课退费、求职内推费 |
| 老年 | 25 关 | 冒充孙子、养老金认证、民族资产解冻、收藏品鉴定费、上门安装、以房养老、社保「补缴」 |

中年局会掺入 1 关老年线的骗局（老年局反之）——模拟「骗子不按年龄线出牌」的现实。

其中 **4 关是「多轮关卡」**：不止一次选择，先看你第一反应，骗子再根据你的反应换话术，
最后才到关键决断。抵抗型和配合型会走进**不同的第二幕**。

## 特色

- **三档判定，不是简单的对错两分**
  选对了是**守住**；选错了但没全错、信息没外流是**中招**；全错的那种才叫**泄露**。

- **每关即时复盘**
  每次选择后都给一页复盘：先告诉你这一选实际发生了什么，**选错时直接摆出「✅ 正确做法」**
  （把正确选项的具体动作原文给你看），最后附一条能记住的防骗知识点。

- **防骗笔记（错题本）**
  结算后生成独立一页，按「需要复习 / 已经守住」分区罗列本局关卡，错过的会显示「我当时选了…」，
  顶部给出「本局最该记住的一条」。整页是一张**可直接保存的图片**（手机长按存相册）。

- **防骗性格测试**
  12 道情境题覆盖 4 个维度，给出性格画像与针对性建议。
  **独立题库，不玩也能测**；同一套答案结果恒定。测过之后防骗笔记里会多出一块性格区。

- **留言墙**
  结算页底部的公开留言板，「说说你差点被骗的那一次」。
  发言门槛是**必须先玩过一局**，且留言会自动带上本局成绩与身份线。

- **打败多少人的百分位** + **全球累计人次**

## 如何运行

**方式一：直接双击** `index.html`，浏览器打开即玩。

**方式二：本地起个 http 服务**（推荐，避免个别浏览器对 `file://` 的限制）

```bash
python -m http.server 8080      # 然后打开 http://localhost:8080
# 或
npx serve
```

## 如何修改内容

所有关卡、话术、选项、知识点都集中在 **`levels.js`**，按身份线分三个数组：
`mid`（中年 25 关）、`youth`（青年 25 关）、`elder`（老年 25 关），三条线共用同一套结构。

### 单轮关卡

```js
{
  title:'关卡名',
  intro:['来源标签','一句话引子'],
  chat:[ {who:'scam',text:'骗子说…'}, {who:'me',text:'你回…'} ],   // 高仿聊天
  leakExtra:'（信息已泄露）后续精准话术补刀',                        // leakLevel>0 时显示
  options:[
    {tag:'best', label:'最优选择文案', verdict:'safe', vtext:'🛡️ 脱险', desc:'复盘', leak:0},
    {tag:'ok',   label:'次优选择文案', verdict:'risk', vtext:'⚠️ 中招', desc:'复盘', leak:0},
    {tag:'bad',  label:'最差选择文案', verdict:'hit',  vtext:'💥 信息泄露', desc:'复盘', leak:1},
  ],
  kp:'防骗知识点'
}
```

### 多轮关卡

多轮关卡把 `options` 换成 `steps`，每个决策点有自己的 `message` 和 `choices`：

```js
{
  id:'mid-xxx', title:'关卡名', category:'…', difficulty:'…',
  psychology:['authority','urgency'], intro:[…],
  steps:[
    // 非终局：选项带 next（指向 steps 数组下标）
    { message:[…], choices:[
        { label:'…', reply:[{who:'scam',text:'骗子怎么回应'}], next:2 },
        { label:'…', reply:[…], next:1 } ] },
    // 终局：选项带 tag，不带 next
    { message:[…], choices:[
        { tag:'best', label:'…', desc:'…', guide:'…' },
        { tag:'ok',   label:'…', desc:'…', guide:'…' },
        { tag:'bad',  label:'…', desc:'…', guide:'…' } ] },
  ],
  kp:'…', guide:'…', leakExtra:'…'
}
```

**关键规则**：*终局* 的判据是「**这一步的选项有没有 `next`**」，不是「是不是最后一步」。
所以一关可以有**多个终局**——比如「刷单返利」第 1 步的选项 `next:[2,1,1]`：
配合型走进第 2 步，抵抗型直接跳到第 3 步，两条支路各自有独立的 best/ok/bad 结局。

### 三档语义（不可变）

| `tag` | 含义 | `verdict` | `leak` | 计分 |
|---|---|---|---|---|
| `best` | 成功守住 | `safe` | 0 | **+20** |
| `ok` | 中招：选错了但没全错、信息没外流 | `risk` | 0 | **+10** |
| `bad` | 泄露：全错的那种，信息已外流 | `hit` | 1 | **0** |

总分 = `(守住关数×20 + 中招关数×10) / (关数×20) × 100`，上限 100。
三档互斥，相加恒为**本局关数**。

> 三档的界面措辞由 `VTEXT` / `VSUB` 两个映射统一管理，改文案不必动上百条关卡数据。

### 对话气泡的 `who` 取值（只有 4 个合法）

| `who` | 样式 | 用途 |
|---|---|---|
| `scam` | 左浮、灰底 | 骗子说话 |
| `me` | 右浮、绿底 | **玩家自己说的话** |
| `sys` | 整行、暖黄底 | **旁白 / 系统提示**（整句带括号的那种） |
| `leak` | 左浮、红底 | 已弃用（会剧透） |

⚠️ 旁白必须用 `sys`。错写成 `me` 会渲染成玩家自己发的绿色气泡。

### 新增关卡时的文案标准

选项的**迷惑性**是这个游戏的核心。三个选项都要是「正常人真会做的选择」，靠细节差异区分，不靠情绪词：

1. **正确项给具体动作，不给态度表态**
   写「打银行卡背面的官方客服电话报卡号查这笔消费」，不写「这是骗局，直接拉黑」
2. **错误项要听起来合理，只是省了关键一步**
   写「问了对方工号和部门，觉得对得上就照做」，不写「怕连累家人所以转账」
3. **禁用情绪暗示词**
   「怕」「心疼」「慌」「心动」「不舍得」这类词等于在提示「选这个就是被操控了」
4. **三个选项长度要对齐**
   否则玩家只看长度就能猜出答案——这一条是实测出来的：
   早期版本里「正确项恰好是最长的」占 90%，玩家挑最长的就能全对。
   现在已压到 38%（随机约 33%，基本无信号）。

> 改完刷新浏览器即可生效，无需构建。

## 技术说明

- **游戏本体零依赖**：结构、样式、逻辑都在单个 `index.html` 里，改完无需构建。
- **关卡数据同仓加载**：`<script src="levels.js">` 同步加载一份（离线双击也能玩），
  另有一次带时间戳的异步 fetch 用于**绕开浏览器缓存**——改完关卡刷新即最新，
  不必等 GitHub Pages 那 10 分钟缓存过期。fetch 失败会静默沿用本地那份，不影响游玩。
- **留言墙后端是 Supabase**：唯一需要外部服务的功能。
  用 Postgres 存留言，前端通过 REST 读写；发布走数据库函数（RPC），
  **限流逻辑放在数据库侧**——前端那个冷却只改 localStorage 就绕过了，只有服务端的计数才算数。
- **留言墙安全模型（三层）**：
  1. 表开启 RLS；
  2. 匿名角色只被授予 `SELECT` / `INSERT`，**显式 revoke 掉 `UPDATE` / `DELETE`** ——
     所以任何人按 F12 也删不掉、改不了别人的留言；
  3. 前端只查 `is_hidden = false` 的行，被后台隐藏的留言对访客不可见。

  前端**不持有任何删除凭据**，删除只能从 Supabase 后台做。
  ⚠️ `index.html` 里那个 `sb_publishable_…` 是**公开级别**的 key，设计上就是给浏览器用的；
  绝不要把它换成 `sb_secret_` / `service_role`——那会绕过全部安全规则。
  （代码里有哨兵拦截这种误填，会在控制台报错并自动停用留言墙。）
- **后端没配好游戏也能玩**：留言区会提示「留言功能还在准备中」，其余功能不受影响。
- **近似百分位**：静态站没有数据库，思路是借第三方免费计数服务当「分桶存储」——
  把分数划成若干段，每段一个独立计数器，读回来在前端算百分位（分段粒度较粗，属近似值）。
- **站内返回**：接入了 History API，手机侧滑返回和浏览器后退是**在站内退上一层**，
  不会把整个页面退掉。
- **结果卡是画出来的**：性格结果卡不是 DOM 排版，而是用 Canvas 绘成图片再以 `<img>` 显示
  ——所以手机上长按就能存相册，且所见即所存。
- **移动端适配**：聊天气泡布局为窄屏优化；输入框字号设 16px 以避免 iOS 聚焦时自动放大页面。

## 如何部署

本项目托管在 **GitHub Pages**，推送到仓库后自动构建，无需任何配置。

若要部署到自己名下：fork 本仓库，在 Settings → Pages 里把 Source 设为 `main` 分支根目录即可。

> 留言墙后端与托管方式无关，换托管不需要重新配置数据库。
