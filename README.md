# 反诈先锋 - 21天防骗挑战（本地离线版）

一款网页文字反诈游戏：抽身份牌 → 进入 21 天「被骗风险期」→ 每局抽 5 关（中年 20 关 / 青年 15 关 / 老年 15 关，**中老年两池互掺 1 关**，青年线纯净）→ 高仿微信聊天气泡做抉择 → 信息泄露链越滚越狠 → 结算防骗分与称号。

本目录是**完全离线、零依赖**的本地项目，不依赖任何在线服务，双击即可在浏览器游玩。

## 目录结构

```
reborn-antifraud-local/
├── index.html        # 游戏本体（结构+样式+逻辑）
├── levels.js         # 关卡数据：中年 20 / 青年 15 / 老年 15 关（只改这里就能加关/改话术）
├── assets/
│   ├── share-cover.png  # 分享卡片封面（og:image，1200x630，脚本 _mkcover.py 生成）
│   ├── youth.png     # 青年身份牌图标
│   ├── mid.png       # 中年身份牌图标
│   └── elder.png     # 老年身份牌图标
├── serve.bat         # Windows 一键本地预览（起 http 服务并打开浏览器）
├── deploy.md         # 部署到 Cloudflare Pages 的说明
└── README.md         # 本文件
```

## 如何运行

**方式一：直接双击**
双击 `index.html`，浏览器打开即玩（手机端体验最佳，已做移动端适配）。

**方式二：本地预览服务器（推荐，避免个别浏览器对 file:// 的限制）**
双击 `serve.bat`，会自动打开 `http://localhost:8080`。
> 没有 Python 时，改用 `npx serve` 或 VS Code 的 Live Server 插件。

## 如何修改内容

所有关卡、话术、选项、知识点都集中在 **`levels.js`** 里，按身份线分三个数组：`mid`（中年 20 关）、`youth`（青年 15 关）、`elder`（老年 15 关）。三条线共用同一套关卡结构：

- 每关结构（以 `mid` 为例，`youth` / `elder` 完全相同）：
  ```js
  {
    title:'关卡名',
    intro:['来源标签','一句话引子'],
    chat:[ {who:'scam',text:'骗子说…'}, {who:'me',text:'你回…'}, … ],  // 高仿聊天
    leakExtra:'（信息已泄露）后续精准话术补刀',                         // leakLevel>0 时显示
    options:[
      {tag:'best', label:'最优选择文案', verdict:'safe', vtext:'🛡️ 脱险', desc:'复盘', leak:0},
      {tag:'ok',   label:'次优选择文案', verdict:'risk', vtext:'⚠️ 中招', desc:'复盘', leak:0},
      {tag:'bad',  label:'最差选择文案', verdict:'hit',  vtext:'💥 信息泄露', desc:'复盘', leak:1},
    ],
    kp:'防骗知识点'
  }
  ```
- **三档判定口径**（`index.html` 的 `choose()` 里，三档互斥、相加恒为 5）：
  | 选项 tag | 含义 | 计入统计 | 计分 |
  |---|---|---|---|
  | `best` | 选对了，成功守住 | 守住关数 | +20 |
  | `ok` | **中招**：选错了，但没全错、信息没外流 | 中招关数 | −10 |
  | `bad` | **泄露**：全错的那种，信息已外流 | 泄露次数 | −25 |
  > 结算页三个数字相加 = 本局关数（5）。术语以 `VTEXT` / `VSUB` 两个映射统一覆盖，改文案不用动 150 条关卡数据。
- **加关**：往对应身份线的数组里照格式新增一个对象即可（给老年线加关就加进 `elder`），游戏会自动纳入随机池。
- **改话术**：直接改 `chat` / `options` 的文案。
- **写选项的三条铁律**（50 关已按此标准重写过一遍，新增关卡请沿用）：
  1. **正确项给具体动作，不给态度表态**——写"打银行卡背面的官方客服电话报卡号查这笔消费"，不写"这是骗局，直接拉黑"
  2. **错误项要听起来合理，只是省了关键一步**——写"问了对方工号和部门，觉得对得上就照做"，不写"怕连累家人所以转账"
  3. **禁用情绪暗示词**——`怕` / `心疼` / `慌` / `心动` / `不舍得` 这类词等于在提示"选这个就是被操控了"，三个选项必须长度语气对齐
  > 中间项（`ok`）的标准是"部分正确但不彻底"：守住钱但泄露了信息，或加了微信但没给验证码。
- **难度**：评分在 `index.html` 的 `endGame()` 里（`cleared*20 - busted*10 - leakLevel*25`，满分 100 = 五关全守）。

> 改完刷新浏览器即可生效，无需构建。

## 「打败了 X% 的人」实现说明

**思路**：静态站没有数据库，但 Abacus 的计数器可以当"分桶存储"用——把分数划成 11 段，每段一个独立 key，读回来在前端算百分位。

- 分段：`0-9 / 10-19 / … / 90-99 / 100`，key 形如 `reborn-antifraud-2026/b40`
- 结算时 `computeBeat(sc)`：
  1. `hit` 把自己计入所在段（桶不存在时 Abacus 会自动创建）
  2. 并发 `get` 全部 11 段（各 5 秒超时，互不影响）
  3. 百分位 = **严格低于我所在段的人数 / 可达段总人数**，钳制在 1~99
- 文案按档位分级：≥95% / ≥80% / ≥50% / ≥20% / 低于 20%
- **降级**：任一段不可达就跳过该段（不拖垮整体）；全部不可达则整块隐藏，不报错
- ⚠️ 关键：**写和读必须共用同一套 key**（`BUCKETS` 数组 → `bucketKey()`），早期版本写了 `b10` 却去读 `b0_10_20_30` 这种合并 key，对不上导致永远算不出来
- 已知局限：这是**近似百分位**（分桶粒度较粗，同段内不区分高低），且 Abacus 为社区公益服务无 SLA

## 防骗性格测试（16 型 / 12 题）实现说明

MBTI 式的四维结构：**4 维 × 2 极 = 16 型**，类型码由四个字母拼成（如 `AGSD`）。

| 维度 | 问题 | 两极 |
|---|---|---|
| ① 信什么 | 你更容易被哪类身份骗到 | `A` 权威（机构/客服/公检法） / `K` 亲缘（熟人/亲戚/孩子） |
| ② 图什么 | 你更容易被哪种诱因勾住 | `G` 贪利（机会/收益/便宜） / `L` 避害（害怕/损失/麻烦） |
| ③ 靠什么 | 遇事你靠什么做判断 | `S` 独断（自己扛/不说） / `V` 求证（去问/去核） |
| ④ 什么时候 | 你的决策节奏 | `R` 急躁（当场就办） / `D` 拖延（放着再想） |

### ⚠️ 关键设计：独立固定题库，不复用本局关卡

**测试用的是 `PTEST` 里 12 道固定情境题，四维各 3 题，和本局随机抽到哪 5 关完全无关。**

早期版本（v1）拿"本局失守的关"判性格，有两个硬伤：

1. **结果不可复现**：每局抽到的关卡不同、选项不同，同一个人两次测出来类型不一样，说服力为零
2. **题量太少**：5 题里往往只有 2~3 处失守，四维各分不到 1 题，等于靠随机数决定性格

现在改成独立题库后，同一套答案**每次结果完全一致**（测试脚本会验证这一点）。

### 计分与映射

- 每题三个选项各标一个极（**短码** `a/k/g/l/s/v/r/d`），每题都刻意覆盖两极，避免必平
- `scorePT()`：先经 `PT_LONG` 把短码转成长名（`a→auth`、`k→kin`…），再统计各极命中次数
  - ⚠️ **这里踩过坑**：早期版本直接拿短码去查长名计数表，`c['a']` 恒为 `undefined`，所有计数都是 0，结果**每次都退回兜底的 `AGSD`**。改题库时务必保证 `PT_LONG` 与 `PTEST` 的 `k` 一致
- 取每维**命中更多**的一极；**打平时按更保守的方向落**（`auth` / `gain` / `verify` / `delay`），保证结果稳定不跳变
- 同时输出 `strength`（该极在 3 题里中几题），在四维条右侧显示为 `2/3` 这样的强度标
- 拼成四位码 → 查 `PERSONA` 表（16 条，每条含 `n` 类型名 / `d` 画像 / `a` 建议）

### 入口与展示

- **结算页**：原「称号」栏位改成性格测试区块（`.pt-box`）。未测时显示"12 道情境题，测你的防骗性格"+开始按钮；测完原地回填类型名，点进完整卡片
- **首页**：底部有「🧭 不玩游戏，直接测防骗性格（12 题）」，不玩也能测
- 结果卡片在 `s-persona` 屏，含类型名 / 四位码与四维全称 / 画像 / 四维条（带强度）/ 建议 / 口径说明

### 题目设计原则

三个选项都要是"正常人会做的选择"，靠**细节差异**区分，不靠情绪词：

- 正确项给**具体核实动作**，不给态度表态（写"打银行卡背面的官方客服电话报卡号查这笔消费"，不写"这是骗局，直接拉黑"）
- 错误项**听起来合理但省了关键一步**（写"问了对方工号和部门，觉得对得上就照做"，不写"怕连累家人所以转账"）
- 中间项做**部分正确但不彻底**（守住钱但泄露了信息，或加了微信但没给验证码）

### 合规与风控（起名时踩过的坑）

- **「反诈先锋」是有官方前身的词**：广东省反诈中心 2018 年就上线过同名预警 APP。好处是可信度背书，坏处是**可能被平台误判为政务内容而降推荐权重**，用户也会误以为是官方出品。→ 因此结算页加了 `.disclaimer` 明确写着「情景模拟，「写点知识」出品，非官方产品」。
- **避开「打假/揭秘/曝光/喊话」类词**：抖音正在治理「以反诈为噱头煽动情绪收割流量」，160 万粉的头部反诈账号已被封，这些词会把内容划进同类风控画像。
- **标题里不要出现「投资/高收益/内部渠道/稳赚」**，即使是反讽语境，也容易触发「涉诈引流」识别。
- **标注虚构**：金额与情节都是设定，分享卡与首页都标注了「情景模拟」，既合规也避免被当真事传播。
- 规避广告法极限词（最/第一/唯一/100%），所以文案里没有「绝对不会被骗」这类表述。

## 防骗笔记实现要点

- `choose()` 里把每关选择压入 `state.log`（`title` / `kp` / `tag` / `verdict` / `myLabel` / `desc`），`startLine()` 重置为 `[]`
- `buildNote()` 拼 HTML：三栏统计 → 最该记住的一条 → 需要复习区（`showMy=true`，附"我当时选了…"）→ 已经守住区（只列知识点）→ 品牌引导footer
- 术语徽章按 `tag` 上色（`badge best/ok/bad`），与选项反馈的 `VTEXT` 口径一致
- 全对时显示「🎉 五关全守住，本局没有错题」且不渲染复习区；全错时不渲染守住区
- 所有关卡文案经 `esc()` 转义后再插入 `innerHTML`

### 与防骗性格的动态联动

笔记里的「防骗性格」区是**条件渲染**的，靠一个模块级变量 `ptResult` 控制：

| `ptResult` | 笔记表现 |
|---|---|
| `null`（没测过） | **整块不出现**，笔记保持原样，footer 用默认文案 |
| 对象（测完了） | hero 之后插入 `.note-persona` 区；footer 换成带类型名的传播文案 |

- `finishPTest()` 里 `ptResult = scorePT()` 写入；`ptResult` 默认声明为 `null`，所以「不玩游戏直接看笔记」永远不会多出这一区
- `buildNotePersona()` 首行 `if(!ptResult) return '';` 就是"没测就不加"的唯一开关，**不要在 `buildNote()` 里另外判断**，否则两处判断迟早不同步
- 区块内容：类型码 → 类型名 → 四维（只列**偏向的那一极**，附 `x/3` 强度）→ 该人格的针对性建议
- 四维展示顺序固定为 信什么 / 图什么 / 靠什么 / 什么时候，与结果卡片口径一致
- footer 分流：测过 →「把这张转给家里人 —— 你的『XX』弱点，可能正是他们的强项」；没测 →「骗子的话术一直在变，套路从来没变」
- 重测会直接覆盖 `ptResult`（赋值而非追加），所以不会出现两套维度叠加
- 类型名与建议经 `esc()` 转义；验证时用**注入式断言**（把人格名改成 `<img src=x onerror=...>`，断言输出含 `&lt;img` 且不含裸 `<img`）

## 部署与更新流程（重要）

本项目部署在 GitHub Pages（双仓：网页 `FZXF` + 数据 `FZXF-data`）。

> ⚠️ **本机 git 走不通**：环境代理只放行 curl，git 的 CONNECT 隧道会 502，`git push` / `git fetch` 均失败。
> **更新网页的正确姿势**：改本地文件后，用 GitHub Contents API 提交（`PUT /repos/{owner}/{repo}/contents/{path}`，body 带 `message` / `content`(base64) / `sha`(线上当前 sha) / `branch`），走 curl 由代理放行。
> 本地 git 仓库仅作版本留档，与远程历史可能分叉，不影响 API 提交。
> 提交后 CDN 缓存需 **40~60 秒**才刷新，验证时先查 `/pages/builds/latest` 确认 `built`，再加 `?cb=时间戳` 重新拉取。

- 计数键：`reborn-antifraud-2026 / plays`，**到达结算页才算 1 人次**（点开没玩完的不计）
- 首页加载用 `get` 只读刷新；结算时用 `hit` +1；两次请求都带 5~6 秒超时，失败静默降级
- 降级行为：结算页改显"本机第 N 局（全球统计暂时不可达）"，首页显示上次缓存的全球数
- ⚠️ 该服务为社区公益项目，无 SLA；若日后失效或想要自有数据，部署到 Cloudflare Pages 时可升级为 **Pages Function + KV** 自建计数（前端只需把 `COUNT_URL` 指向自己的 Function 即可）
